# ROUTEQ｜質問確認トークン再利用と二重受付の検証（2026-10-21）

対象: TESTブランチの `訂正シート最優先・直接参照.gs`（SHA `121de2f7b14a43cba937a5baa26decd398f896b5`）。本番・TEST GAS・Sheetsを実行せず、読み取り検証。

## 実測したこと
`consumeRouteValidationToken_` のソース本体を抽出し、指紋・署名を固定モックに差し替えて同一トークンを2度検査した結果:
- 初回: true
- 2回目: true
- 署名検査だけで、トークンを消費済みとして永続化する処理はない。

`saveQuestionForWeb_` は上記トークン検証後、Lock内でQuestionsへ新規行を作成しUsersの利用回数を加算する。検査対象部分に送信IDや既存の同一リクエスト照合は確認できない。

## 判定
**不合格候補 P0: 同一トークン・同一質問の重複送信で二重登録/二重回数消費する可能性。** 静的制御フローと署名検証関数の再利用試験から指摘したもので、質問受付全体を実行した二重登録再現試験は未実施。従前の「トークン消費後に再試行できない」という報告は誤りであり訂正する。

## 必須修正条件
- サーバー側で一意の送信IDを発行/受付し、Lock下で永続的に重複判定する。
- 同一送信ID再試行は既存質問の状態を返し、新規Questions行追加・Users回数消費を行わない。
- 別送信IDの意図的な同文質問は別受付として扱う。
- Questions追加成功後のUsers失敗と補償削除不能、AI生成成功後の再試行でも重複しないことを障害注入検証する。
- ID一致かつ内容不一致の場合はfail-closedとする。
- 既存の隔離ガード、外部通信禁止を維持する。

実GAS/Sheets E2Eと本番同等性は未検収。Work側で同一コードを並行修正中の可能性があるため、本報告では実装コードを変更しない。
