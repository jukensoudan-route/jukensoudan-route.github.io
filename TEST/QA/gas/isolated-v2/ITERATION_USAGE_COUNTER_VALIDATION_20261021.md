# ROUTEQ｜反復修正：質問受付の残回数・使用回数の不正値拒否（2026-10-21）

## 発見
`訂正シート最優先・直接参照.gs:saveQuestionForWeb_` のロック内処理で Users の残回数・使用回数を `Number(...)` で変換していた。残回数が数値以外の場合は `NaN <= 0` が false となり、質問行に異常値を書いたうえで使用回数や残回数の計算を破損する危険があった。マイナスや小数、使用回数側の不正値にも妥当性検査がなかった。

## 修正
`remaining` と `usedCount` は `Number.isSafeInteger` で0以上の整数に限定。利用回数は既存の「0なら質問不可」を維持。使用回数の+1が安全整数範囲を超える場合も拒否。検査は質問行・Users更新に入る前のロック内で行う。変更先はTESTブランチ `isolated-v2` の対象ファイルのみ。

## 実ソース由来のロジック検査
残回数1/使用0、残回数5/使用2、残0、残数文字列、残数小数、残数負、使用数文字列、使用数負、使用数小数の9ケース：全PASS。
保存済み14ファイル連結JavaScript構文：PASS。GitHub更新後の再取得全文照合：PASS。

## 未解決
質問保存→Users更新の複数Sheets書込みはGoogle Sheetsの単一トランザクションではない。途中で書込みエラーになった場合の原子的整合性や補償処理は未検証。LINE認証・AI回答・外部送信・決済連携の正常動作も未検証。

**判定：回数値の不正入力拒否を単体模擬検収済み。本番同等ミラー完成ではない。** 本番GAS、実TEST GAS、Sheets、main、原本には変更なし。
