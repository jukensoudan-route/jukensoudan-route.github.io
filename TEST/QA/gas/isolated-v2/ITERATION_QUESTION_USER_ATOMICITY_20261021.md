# ROUTEQ｜質問保存・利用回数の途中失敗検査と修正（2026-10-21）

## 再現した不具合
元の`saveQuestionForWeb_`はQuestionsへ質問行保存後、Usersの使用回数・残回数等をセルごとに更新していた。途中のUsers残回数セル書込みに失敗すると、質問行は作成済み、使用回数のみ増加、残回数は未減算となり不整合が実際にモックで再現した。

## 修正
Users行の値12列を元データから構成し、表示名・使用回数・残回数・無料体験使用フラグ・更新日時を**単一のsetValues呼出**でまとめて更新するように修正した。変更は`isolated-v2/訂正シート最優先・直接参照.gs`のみ。本番GAS、実シート、main、原本は変更なし。

## 修正後実ソースによる模擬試験（4件PASS）
1. 質問受付正常完了：Questions追加、Users残回数1→0、使用回数0→1、Users一括書込み1回：PASS
2. 事前確認トークン無効：質問・利用回数とも変更なし：PASS
3. Questionsへの書込み失敗：Usersへの回数変更なし、ロック解放：PASS
4. Users一括書込み失敗：Usersの使用回数・残回数・無料試用フラグはいずれも変化なし：PASS

JavaScriptのインメモリSheet/Lock/LINE認証/AI生成モックで保存済み**実ソース**を呼び出した。GitHub保存・再取得全文一致PASS。**Google SheetsにおけるsetValuesはトランザクション保証を意味しない。**

## 重大な残課題
Questionsの保存に成功しUsers一括書込みが失敗した場合、質問行だけが残る（4件目で再現）。質問とUsersにまたがる整合性と再実行時の重複防止・回復は未解決。書込み失敗を自動成功扱いにしてはならない。実TEST GASの展開、AI/LINE/Stripe/返信予約の本番同等性も未検収。**ミラー完成判定：不可。**
