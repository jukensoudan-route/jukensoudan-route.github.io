# ROUTEQ｜Stripe付与再試行の二重付与防止改修（2026-10-21）

## 問題
元の付与処理はUsersへの残回数付与が成功してからPaymentsを「付与済」に更新していたため、Payments更新失敗後の再実行で同一決済を再度付与し得た。既存の完了状態のチェックだけでは不十分だった。

## TESTブランチ修正
- Script Lock内でUsersを更新する**前**に、決済SessionをPaymentsへ「付与処理中」として先行記録する。
- Sessionが「付与処理中」または「要整合確認」なら自動再付与せず、手動照合要求。
- Users一括更新成功後にPaymentsの「付与済」へ確定。確定更新が失敗しても「付与処理中」が残り、自動二重付与を抑止する。
- 同じPayment Intentが別Session IDで登録されていた場合は、完了以外も含めて自動付与を拒否する。
- 従前のTEST環境ガードおよびセンシティブ入口停止は維持。本番GAS・Sheets・Stripe・LINEは無変更。

## 実ソースを使用したオフライン障害注入試験
次のケースを実行し、期待どおりの状態遷移を確認：
1. 正常付与：残0→5、Payments「付与済」
2. 完了Session再試行：追加付与なし
3. Users更新後のPayments確定失敗：残5、「付与処理中」のまま
4. その再試行：「状態未確定」エラー、追加付与なし
5. Users更新自体の失敗：「付与処理中」、残0
6. その再試行：追加付与を行わず手動確認を要求
7. Paymentsの先行書込み失敗：Users残回数を変更しない

試験1〜7は2026-10-21の実ソースモックで期待状態を確認。追加した別Session同一Payment Intentの拒否は静的構文検査・保存・再取得照合済み（個別の動的試験は未実施）。

## 依然として残る重大課題
- 保留中の決済が**すでに付与済か、まだ付与されていないか**を自動判別・復旧する仕組みは未完成。これを解決しない限り「自動復旧も本番同等」は未合格。
- Google Sheets跨ぎのトランザクション/実行中断時整合性は保証できない。
- 実GASでの接続・デプロイ・Stripe TEST決済・Webhook・LINE/AI連携は未検収。
- **今回の修正は二重付与防止のfail-closed措置。商用ミラー完成ではない。**
